# 钉钉登录问题诊断指南

## 问题描述

用户在使用钉钉扫码登录时遇到"登录失败：钉钉未返回可验证的组织身份"错误。

## 已修复内容

### 1. 增强日志记录

在 `internal/api/handlers.go` 的 `DingTalkCallback` 函数中添加了详细的调试日志：

- **记录钉钉返回的原始数据**：完整的 JSON 响应
- **记录解析后的字段**：`associated_user_id`、`unionID`、`openID`
- **记录用户匹配过程**：按 userid 查找、按邮箱/手机号查找
- **记录失败原因**：详细的错误信息和上下文

### 2. 改进匹配逻辑

原来的逻辑：
```go
if dtUserID == "" && openID == "" {
    return "missing dingtalk user identity"
}
```

新的逻辑：
- 即使没有 `userid` 和 `openID`，也尝试通过邮箱或手机号匹配
- 优先使用 `associated_user_id`
- 其次尝试通过 `unionID` 解析 `userid`
- 最后通过邮箱或手机号匹配本地用户

### 3. 更友好的错误提示

在找不到用户时，记录更多诊断信息：
- 钉钉返回的身份标识
- 用户姓名
- 邮箱和手机号

## 使用说明

### 1. 查看日志

重启服务后，当用户尝试登录时，查看后端日志：

```bash
# 在服务器上查看实时日志
tail -f /path/to/your/log/file

# 或者在 Docker 环境中
docker-compose logs -f backend
```

### 2. 分析日志输出

日志会包含以下信息：

```
[dingtalk/callback] host=xxx has_code=true has_state=true
[dingtalk/callback] user_info_raw: {"unionId":"xxx","openId":"xxx","nick":"张三","email":"xxx@example.com"}
[dingtalk/callback] parsed: associated_user_id=, unionid=xxx123, openid=yyy456
[dingtalk/callback] resolved userid from unionid: userid123
[dingtalk/callback] extracted info: name=张三, email=zhangsan@example.com, mobile=13800138000
[dingtalk/callback] user found by userid: user_id=userid123
```

### 3. 常见问题排查

#### 问题 1：钉钉未返回 `associated_user_id`

**原因**：钉钉扫码登录返回的是个人账号信息，不包含企业内的 `userid`

**解决方案**：
1. 检查是否返回了 `unionID`
2. 如果有 `unionID`，系统会自动调用 `GetUserIDByUnionID` 解析企业内 `userid`
3. 如果解析失败，检查钉钉应用权限配置

#### 问题 2：找不到本地用户

**原因**：用户未同步到本地数据库

**解决方案**：
1. 在管理后台执行"同步组织数据"
2. 确保钉钉应用有读取企业通讯录的权限
3. 检查日志中的 `email` 和 `mobile` 是否与本地用户匹配

#### 问题 3：`GetUserIDByUnionID` 调用失败

**原因**：钉钉应用权限不足或 `unionID` 无效

**解决方案**：
1. 检查钉钉开放平台应用配置
2. 确认应用有以下权限：
   - `Contact.User.Read`（读取通讯录用户信息）
   - `openid`（获取用户 openid）
   - `corpid`（获取企业信息）

## 钉钉应用配置检查清单

### 1. OAuth 2.0 授权范围

在钉钉开放平台应用设置中，确保配置了以下 scope：

- `openid`
- `corpid`
- `Contact.User.Read`

### 2. 回调地址配置

确保回调地址正确配置：

```
https://your-domain.com/callback
```

或在环境变量中设置：

```bash
DINGTALK_REDIRECT_URI=https://your-domain.com/callback
DINGTALK_APP_HOME_URL=https://your-domain.com
```

### 3. 服务器出口 IP 白名单

在钉钉开放平台中添加服务器的出口 IP 地址。

### 4. 应用权限

确保应用已开通以下权限：

- 企业通讯录只读权限
- 获取用户 userid 权限
- 通过 unionid 获取 userid 权限

## 环境变量配置

确保以下环境变量正确配置：

```bash
# 钉钉应用配置
DINGTALK_APP_KEY=your_app_key
DINGTALK_APP_SECRET=your_app_secret
DINGTALK_CORP_ID=your_corp_id

# 可选：多组织配置
DINGTALK_ORGANIZATIONS='[{"org_id":"org1","name":"组织1","corp_id":"xxx","app_key":"xxx","app_secret":"xxx","status":"active"}]'

# 回调地址（可选，不配置则自动推断）
DINGTALK_REDIRECT_URI=https://your-domain.com/callback
DINGTALK_APP_HOME_URL=https://your-domain.com
```

## 测试步骤

1. **重启服务**：
   ```bash
   docker-compose restart backend
   ```

2. **清理浏览器缓存**：删除 cookie 和缓存

3. **尝试登录**：扫码登录

4. **查看日志**：
   ```bash
   docker-compose logs -f backend | grep "dingtalk/callback"
   ```

5. **分析结果**：
   - 如果看到 `user found by userid` 或 `user found by email/mobile`，说明匹配成功
   - 如果看到 `user not found`，记录日志中的诊断信息

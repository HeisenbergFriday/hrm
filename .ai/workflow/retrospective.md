# 阶段六：收尾

## 步骤 16：文档更新与复盘

### AI 文档更新判断

| 变化 | 更新位置 |
|---|---|
| 新目录、模块、入口、路由、模型分组 | `.ai/PROJECT_MAP.md` |
| 单模块长期业务规则 | `.ai/MODULES/<module>.md` |
| 架构、数据流、跨模块、多租户边界 | `.ai/ARCHITECTURE.md` |
| 编码、命名、错误处理、测试习惯 | `.ai/CONVENTIONS.md` |
| 开发、测试、构建、部署命令 | `.ai/COMMANDS.md` |
| UI 组件、布局、交互和无障碍规范 | `.ai/DESIGN_SYSTEM.md` |
| AI 协作、读取策略、文档分层 | `AGENTS.md`、`CLAUDE.md`、`.ai/AI_WORKFLOW.md` 或阶段文档 |
| 普通实现细节，没有长期知识 | 不更新 AI 文档 |

不要默认更新根规则；业务知识优先进入模块文档。

### 开发问题记录

收尾前判断 `docs/DEVELOPMENT_ISSUES.md` 索引及对应年度归档：

| 情况 | 动作 |
|---|---|
| 已定位且可复用的根因 | 在 `docs/development-issues/YYYY.md` 新增条目，或更新同根因条目；同步顶部索引 |
| 同根因再次出现 | 更新对应年度归档中的原条目，禁止重复开条；同步顶部索引 |
| 一次性环境/外部工具故障，无项目改进项 | 不记录，最终总结说明 |
| 敏感信息 | 禁止写入 |

记录字段：日期、级别、模块/标签、范围、现象、根因、修复、验证、防复发、状态。

## 根据 git diff 更新 AI 文档

用户明确要求根据当前改动更新文档时，先检查：

```bash
git status --short
git diff --stat
git diff --name-status
git diff --cached --stat
git diff --cached --name-status
```

必要时再查看具体 diff。注意：普通 `git diff` 不包含未跟踪文件，也不一定包含暂存改动。

然后：

1. 判断变更影响的模块、目录、命令、架构和规范。
2. 按上方分层选择最少文档。
3. 不默认更新 `AGENTS.md`。
4. 更新前说明计划。
5. 只修改与实际 diff 一致的内容。

固定输出：

```text
本次变更影响：
- <影响>

计划更新：
- <文档及原因>

不更新：
- <文档及原因>
```

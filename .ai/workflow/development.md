# 阶段三：开发

## 步骤 8：修改前计划

修改文件前输出：

```text
计划修改：
1. <文件>：<原因>

可能影响：
- <调用方、数据、权限、行为>

验证方式：
- <测试/lint/build/人工检查>

适用的防复发约束：
- <问题日志日期/标签/模块，或未发现相关记录>
```

需要改变文件范围或方案时，先说明原因并更新计划。

## 步骤 9：编码实现

### 后端

- 保持 Handler → Service → Repository → Model 分层。
- 参数、错误、日志、事务、锁、幂等和租户作用域完整。
- 外部调用、循环和后台任务正确处理 context、超时和终态持久化。
- 公共 API、数据库字段和状态流转变更必须同步调用方与测试。

### 前端

- 使用 TypeScript、antd 和既有设计系统。
- 处理 Loading、空数据、错误、权限、并发点击和请求竞态。
- 数据权限控制可见数据；功能权限控制操作按钮。缺权限按钮保持可见但禁用并提示。
- 不使用不安全 HTML，不残留调试输出。

### 禁止

- 顺手重构无关代码或批量改格式；
- 引入无关依赖；
- 删除测试、降低校验或伪造成功；
- 未说明就删除现有逻辑；
- 读取或泄露敏感配置；
- 在共享工作区覆盖其他未提交修改。

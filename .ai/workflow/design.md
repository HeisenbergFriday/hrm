# 阶段二：设计

## 步骤 5：技术方案设计

### 触发

- 新业务模块或跨模块功能；
- 数据库结构变化；
- 架构或公共 API 调整；
- 第三方系统集成；
- 高风险权限、金额、持久化、并发或状态流转。

简单 Bug、样式细节、单文件修正和普通配置可跳过正式方案。

### 必须包含

```text
影响范围：
- 模块、调用方、数据流和依赖

实现方案：
- 核心思路
- 关键决策及理由
- 被放弃方案及原因（如有）

数据库（如涉及）：
- 表/字段/索引
- 兼容与迁移顺序
- 回滚方案

API（如涉及）：
- 路径、方法、请求、响应、错误和权限
- 调用方兼容方式

风险：
- 技术、业务、安全、部署风险及缓解措施
```

数据库变更必须评估旧数据、唯一索引、锁表、灰度兼容和回滚。公共契约变化必须检查所有调用方。

## 步骤 6：UI/交互设计确认

### 触发

- 新页面；
- 页面布局变化；
- 新 UI 组件；
- 交互流程或状态流转变化。

现有页面加字段、颜色/间距微调和 Bug 修复通常无需单独确认。

### 执行

1. 读取 `.ai/DESIGN_SYSTEM.md`。
2. 输出页面描述。
3. 用户确认后再编码。

```text
页面描述：
标题/副标题：<内容>
筛选与操作区：<内容>
主体：<表格/卡片/表单及字段>
状态：<Loading/空态/错误/权限/状态标签>
操作：<按钮、确认、反馈>
分页或导航：<内容>
无障碍：<键盘、标签、提示>
```

使用 antd 及现有公共组件；设计描述必须与实现一致。

## 步骤 7：设计评审

新增模块、跨模块、数据库、架构和高风险功能必须评审：

- 影响范围是否完整；
- 数据流与权限边界是否明确；
- 数据库和 API 是否兼容；
- 状态、异常、并发、幂等是否覆盖；
- UI 是否符合设计规范；
- 测试策略和回滚是否可执行。

输出结论：`通过`、`需修改` 或 `不通过`。评审意见未处理前不得进入开发。

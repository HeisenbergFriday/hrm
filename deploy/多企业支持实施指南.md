# 多企业支持实施指南

## 概述

本文档描述如何将 PeopleOps HR 系统从单租户架构升级到多租户架构，支持多个钉钉企业。

## 架构变更

### 1. 数据库层面

#### 新增表
- `organizations` - 企业/组织主表
- `organization_users` - 组织-用户关系表

#### 核心表变更
所有业务表添加 `org_id` 字段作为租户隔离键：
- `users` - 添加 `org_id`，修改唯一索引为 `(org_id, user_id)`
- `departments` - 添加 `org_id`，修改唯一索引为 `(org_id, department_id)`
- 其他38个业务表 - 均添加 `org_id` 字段和索引

### 2. 应用层面

#### JWT Token
- 添加 `org_id` 字段到 Claims
- 每个请求携带用户所属组织信息

#### 登录流程
1. 用户扫码登录钉钉
2. 从 URL 参数或环境变量识别 `org_id`
3. 验证组织是否存在
4. 使用 `(org_id, user_id)` 查找本地用户
5. 生成包含 `org_id` 的 JWT token

#### 数据访问
- 所有查询自动添加 `org_id` 过滤
- Repository 层新增支持多租户的方法
- Service 层调用多租户版本的方法

### 3. 前端层面

#### AuthStore
- 添加 `orgId` 字段
- 登录时存储用户的组织ID

## 注意事项

1. **数据隔离**
   - 所有查询必须包含 `org_id` 过滤
   - 跨企业查询被严格禁止

2. **性能优化**
   - 所有业务表的 `org_id` 字段已建立索引
   - 复合唯一索引确保数据一致性

3. **安全性**
   - JWT token 包含 `org_id`，无法伪造
   - API 自动从 token 提取 `org_id` 进行过滤

4. **兼容性**
   - 现有数据自动迁移到默认组织
   - 旧版 API 仍然可用（使用默认组织）

## 故障排查

### 问题 1：登录后无法看到数据

**原因**：org_id 不匹配

**解决**：
```sql
-- 检查用户的 org_id
SELECT org_id, user_id, name FROM users WHERE user_id = 'xxx';

-- 检查 JWT token 的 org_id
-- 在浏览器控制台解码 token: jwt.io
```

### 问题 2：提示"组织不存在"

**原因**：organizations 表中没有该企业记录

**解决**：
```sql
-- 插入组织记录
INSERT INTO organizations (org_id, name, corp_id, status, created_at, updated_at)
VALUES ('xxx', 'XXX公司', 'dingxxx', 'active', NOW(), NOW());
```

### 问题 3：唯一索引冲突

**原因**：不同企业有相同的 user_id 或 email

**解决**：这是正常的！多租户架构下，唯一索引是 `(org_id, user_id)` 而不是单独的 `user_id`。

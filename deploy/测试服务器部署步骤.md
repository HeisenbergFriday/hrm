## 日志分析

### 成功登录的日志示例

```
[dingtalk/callback] host=xxx has_code=true has_state=true
[dingtalk/callback] user_info_raw: {"unionId":"xxx","nick":"张三","email":"zhangsan@example.com"}
[dingtalk/callback] parsed: associated_user_id=userid123, unionid=xxx, openid=yyy
[dingtalk/callback] extracted info: name=张三, email=zhangsan@example.com, mobile=13800138000
[dingtalk/callback] user found by userid: user_id=userid123
```

### 失败情况的日志特征

#### 情况 1：缺少 userid 但有 unionID

```
[dingtalk/callback] parsed: associated_user_id=, unionid=xxx123, openid=
[dingtalk/callback] resolved userid from unionid: userid456
[dingtalk/callback] user found by userid: user_id=userid456
```

#### 情况 2：通过邮箱/手机号匹配

```
[dingtalk/callback] parsed: associated_user_id=, unionid=, openid=yyy456
[dingtalk/callback] no userid/openid, will try to match by email/mobile
[dingtalk/callback] user not found by userid, trying email/mobile
[dingtalk/callback] user found by email/mobile: user_id=userid789
```

#### 情况 3：用户未同步

```
[dingtalk/callback] user not found by userid, trying email/mobile
[dingtalk/callback] user not found: identity=xxx, name=张三, email=zhangsan@example.com, mobile=13800138000
```

**解决方案**：在后台执行"同步组织数据"

#### 情况 4：API 调用失败

```
[dingtalk/callback] GetUserInfoByCode failed: get dingtalk user info failed: xxx
```

**可能原因**：
- 网络问题
- 钉钉应用权限不足
- AppKey/AppSecret 配置错误

## 钉钉应用配置检查

### 必需的环境变量

```bash
DINGTALK_APP_KEY=your_app_key
DINGTALK_APP_SECRET=your_app_secret
DINGTALK_CORP_ID=your_corp_id
```

### 必需的权限

在钉钉开放平台应用管理中确认以下权限已开通：

1. **OAuth 2.0 授权范围**
   - `openid`
   - `corpid`
   - `Contact.User.Read`

2. **通讯录权限**
   - 企业通讯录只读权限
   - 获取用户 userid 权限
   - 通过 unionid 获取 userid 权限

3. **回调地址**
   - 确保配置了正确的回调地址
   - 格式：`https://your-domain.com/callback`

### 验证配置

```bash
# 测试获取钉钉配置接口
curl -s http://127.0.0.1:18080/api/v1/auth/dingtalk/config | jq

# 应该返回：
# {
#   "code": 200,
#   "data": {
#     "corp_id": "xxx",
#     "client_id": "xxx",
#     "redirect_uri": "https://your-domain.com/callback"
#   }
# }
```
